## 2. 先准备一个明确的钱包和 X 账号

选择自己用于这个项目的独立 EVM 钱包，只记录公开地址。多个浏览器窗口如果属于同一浏览器配置，通常仍共享登录态；需要区分账户时使用独立配置，并在每次操作前看页面实际显示的地址。

特别容易看错的是这三个地址：

1. **EVM 父钱包**：`0x…`，在账户网站的 `Selected Address` 中核对，也是公开 QP 查询使用的地址。
2. **Quip 智能账户**：创建后得到的另一个链上地址，资产可能在这里；不是父钱包地址。
3. **Aglais 矿工地址**：常见为 `5…` 的 SS58 地址，由节点密钥生成；不是比特币地址，也不是 EVM 钱包。

部署脚本只接收第一种公开地址。不要向脚本、评论、Issue 或聊天发送私钥、助记词、恢复口令。

当前 QP 公开前置条件是父钱包关联 X，并关注 `@quipnetwork`。一个 X 能否给多个钱包提供奖励资格、同一人多账户如何计分，公开说明未充分明确，不自行假定。[官方积分规则](https://points.quip.network/)

## 3. Quest 任务怎么做

打开 Quest，核对当前账号，再查看当天仍开放的任务。签到、阅读、测验、加入社区等，以页面实际任务为准；不要重复提交已经完成的项目。

操作后看它是否变成完成状态、积分是否发生变化。访问过链接、打开过页面，不代表任务已经通过。需要提交材料的任务只提交真实完成的内容，不编造贡献或邀请关系。

不同任务可能要求 X 或 Discord 等授权。只完成自己明确要做的任务；验证码、账号授权、钱包签名等步骤由本人核对。没有必要为了“活跃”主动私聊陌生人或反复发无关消息。

记录时写清楚：日期、账号、任务名、提交链接、页面状态、Quest 积分。不要把 Quest 显示的分数填到 QP 节点统计里。

## 4. QP 分类怎么核对

QP 页面会区分登录、资产保管、交换、模拟交换、节点和推荐等类别。观察节点效果时看 `node` 分类，别把登录增加的分数当成节点产出。

官网显示累计已得分和“本周预估”，二者不是同一个统计窗口。模拟交换与真实交换也不同；真实交换涉及真实资产、手续费与链上结算，不要为了教程盲目执行。

使用仓库里的只读查询：

```bash
python3 quipctl.py points 0x你的公开EVM地址 --out ./snapshots
```

它只访问官方公开接口。若返回 `found: false`，应记作“尚未被接口识别”；不能把自动显示的 0 视为已确认的有效账户余额。接口暂未识别也不单独证明操作失败，需要结合网站账户状态和同步情况判断。

## 5. 邀请怎么判断成功

邀请链接格式如下：

```text
https://account.quip.network/?ref=邀请人的公开EVM地址
```

`ref` 是邀请方，网站当前连接的钱包应是受邀方。新账户和邀请方地址不要填反。

可以先在受邀钱包对应的独立浏览器配置中打开链接，检查地址，再按官网流程继续。官方介绍要求通过链接加入并创建账户；邀请是否有效以及是否入账，要看官方记录，不能只凭点过链接判断。

创建 Quip 智能账户本身可能是一笔需要该网络 Gas 的交易。只关联 X、进入创建向导、选择网络或生成了一个待部署地址，不等于已经创建成功。检查页面是否有部署完成的账户，别因为想“看见积分”就默认需要继续充值。

邀请方可公开查询 `referral.refereeCount` 和 `referral.earnedQp`；受邀方可查询是否已被识别。只有人数变化也未必能唯一对应到某一人，最好结合官网给出的明细。没有明细时写“待确认”，不要宣称已完成。

**作者邀请入口（可选，含推荐参数）**：[通过作者链接打开账户](https://account.quip.network/?ref=0xa9EE18b34Ec00664D73d89b8F8BBA68bEB888888)。也可以直接使用无推荐参数的[官方账户网站](https://account.quip.network/)；脚本不会默认把你的节点归到作者地址。

## 6. 普通 CPU 能不能跑

官方支持普通 CPU，也支持 GPU 等计算平台；链上奖励与有效计算能力有关。计算矿工和参与共识出块的正式验证者不是同一种部署目标。[官方矿工说明](https://developers.quip.network/docs/nodes/miners)

本仓库部署的是 CPU 计算矿工，默认每实例 1 核额度、1GiB 内存上限，使用已经校验过创世区块的官方 RPC。它不把你的机器变成已经获批的共识验证者。

实操中，一个矿工忙于计算时可以占满一个逻辑核。CPU 额度 1 核不等于占用很低。内存上限不代表预先占满；在一次运行快照里，五个矿工各约 16～21MiB，但这不是长期峰值，也不是新机器的最低内存承诺。

如果还运行完整链节点，内存和磁盘要另算。我们使用已有链节点时曾看到它约占 3.17GiB 内存；本脚本默认连接已有 RPC，避免每个矿工重复同步全链。公共 RPC 也可能限流或故障，节点能否长期稳定仍要看自己的状态。

## 7. 一键部署

推荐先用有余量的现有 Ubuntu 22.04/24.04 或 Debian 12/13 服务器。准备 Python 3.10+、Docker 和 Compose；CPU 镜像实际验证的是 Linux x86_64，本版本不宣称已经验证 ARM。

先核对环境：

```bash
uname -m
python3 --version
docker --version
docker compose version
free -h
df -h /
```

通常 `x86_64` 对应本工具的部署架构；Python 需要 3.10 或更新版本。`docker` 命令存在但无法连接守护进程时，先检查现有 Docker，别反复覆盖安装。1GiB 是单个矿工容器的上限，宿主机系统和其他服务还要另留资源。

```bash
curl -fL https://raw.githubusercontent.com/q3579338/quip-node-kit/v0.1.0/install.sh -o quip-install.sh
sudo bash quip-install.sh \
  --wallet 0x替换成你的公开EVM地址 \
  --public-host 替换成你的IP或已有网关域名
```

现有服务较多的服务器，先生成计划，确认实例和端口：

```bash
bash quip-install.sh \
  --wallet 0x替换成你的公开EVM地址 \
  --public-host 替换成你的IP或已有网关域名 \
  --dry-run
```

`--dry-run` 不启动容器、不联网校验 RPC、不写运行配置。真正安装才会连接 RPC 和下载官方固定摘要镜像。无 Docker 的新系统可显式增加 `--install-docker`；不要拿这个选项强行覆盖旧 Docker 环境。

这个预演针对矿工部署计划。若使用单独下载的 `install.sh`，引导脚本仍需联网下载并校验管理程序；下载完整仓库后，Python 管理程序本身的预演不联网。

新系统可这样显式安装 Docker 并部署：

```bash
sudo bash quip-install.sh \
  --install-docker \
  --wallet 0x替换成你的公开EVM地址 \
  --public-host 替换成你的IP或已有网关域名
```

自动安装 Docker 仅支持脚本识别的 Ubuntu/Debian，并拒绝覆盖已知冲突环境。其他发行版先按 Docker 官方文档准备环境。

首次启动，官方矿工镜像在服务器本地生成独立节点身份，使用免费测试网水龙头取得 AGLS 并登记。这与向 EVM 智能账户充值 ETH 无关，不要求把主钱包私钥交给服务器。[官方部署说明](https://github.com/QuipNetwork/nodes.quip.network)

## 8. 看见什么才算正在运行

```bash
sudo python3 /opt/quip-node-kit-data/quipctl.py status
```

逐个查看：

- `running: true`：容器正在运行。
- `registered: true`：该矿工身份已经登记。
- `mining: true`：矿工处于计算状态。
- `resultsReceived` 增加：有计算结果返回。
- `nodeAccount`：本实例的矿工地址，应与其他同时运行的实例不同。

这些条件通过后，也不能宣称已经拿到获胜奖励或 QP。普通 CPU 的有效计算结果未必达到获胜门槛，但公开样本里确实存在“当前链获胜为 0、关联钱包节点 QP 为正”的情况。完整计分来源仍要以项目记录核对，不能反推固定每轮给分。

## 9. 一台服务器跑多个

首次安装加 `--instances 4`，即可建立四个各限 1 核的独立矿工。它们共享 RPC，每个单独保存身份和尝试历史。本工具不复制旧密钥来冒充多个节点。

多个计算矿工可以共用已有出站网络。每个独立 IPv6 或不同代理端口不是这份脚本的前置条件，代理端口不同也不保证出口 IP 不同。对外管理入口是否可达是另一项配置：本工具默认只开放本机管理端口，不会因为填了 `public-host` 就替你公开服务。

普通 CPU 多开需要考虑总资源。4 物理核、8 线程不是 8 个独立物理核。超过可见物理核数时必须显式加 `--allow-smt`，并接受实例共享物理核心；占满宿主机后可能影响现有服务。

一个 EVM 地址可以写进多个节点的公开描述，但这不是自动完成的链上钱包授权或 X 关联，也不保证每个节点独立获得一份积分。多个钱包的资格更要按项目规则处理，不以修改 IP、伪造硬件或重复账户来推断合法收益。

有足够核心和内存时，**首次部署**可使用：

```bash
sudo bash quip-install.sh \
  --wallet 0x替换成你的公开EVM地址 \
  --public-host 替换成你的IP或已有网关域名 \
  --instances 4
```

已经按一个实例安装后，不要直接改成四个实例并期待覆盖成功。本版本会拒绝同一状态目录里的不一致参数，保护已有身份。新建另一组需要专门的状态目录、未占用的管理端口，并检查 CPU 分配；默认优先核心可能与旧组重叠，不能只换目录就认定资源已隔离。需要扩容现有组时先做明确迁移计划。

## 10. 怎么测自己的实际积分增量

部署前记一份快照，至少间隔 24 小时再记一份。在同一钱包、同一积分类型下比较：

```bash
python3 quipctl.py points 0x你的公开EVM地址 --out ./snapshots
# 隔天再次执行上面的命令，然后把实际文件名放进下面命令
python3 quipctl.py compare ./snapshots/第一份.json ./snapshots/第二份.json
```

工具只计算两次观测之间的余额差值。若未满 24 小时、钱包不同、账户未识别或出现负向修正，不给出“稳定日收益”。满 24 小时后显示的每24小时折算也只代表该观察窗口。

如果同一个钱包还连着别的服务器，差值是整个钱包的，不是这台机器独有的。测单实例和多实例差异时，应尽量保持观察时长、其他机器、版本和参与状态可比；即使看见增长，也不能凭一次短窗口断定因果。

## 11. 维护和保管

停止用 `stop`，重新启动用 `restart`，不要删除数据目录解决普通故障。每个实例的 `keystore.json` 是节点签名身份；停机后将完整状态目录安全备份到自己控制的位置。不要把备份压缩包、密钥、恢复口令或带 token 的配置上传到 GitHub。

换公开归属地址可用 `set-wallet`；工具保留节点身份并备份配置。换服务器时不要让同一身份在两处同时运行，也不要把本工具安装到现有其他项目的数据目录。

本版本没有自动更新或自动清理功能。链升级时先查官方公告和新版本兼容性；不要为了追版本直接重装、覆盖数据或重新生成身份。

常用命令放在这里，默认 root 部署使用 `/opt/quip-node-kit-data`；自定义目录需要加 `--state-dir`：

```bash
sudo python3 /opt/quip-node-kit-data/quipctl.py status
sudo python3 /opt/quip-node-kit-data/quipctl.py logs --instance 1
sudo python3 /opt/quip-node-kit-data/quipctl.py stop
sudo python3 /opt/quip-node-kit-data/quipctl.py restart
```

只修改某个矿工描述里的公开归属地址：

```bash
sudo python3 /opt/quip-node-kit-data/quipctl.py set-wallet \
  0x替换成新的公开EVM地址 --instance 1
```

这会重启选定矿工以读取新配置，保留节点密钥和历史；配置会先备份。它不会替你关联 X，也不能保证历史积分转移到新地址。

停机备份时，保存整个专用状态目录，至少包含管理记录、配置、各实例身份与所需历史。将备份放在自己控制的私有位置。仓库没有通用跨主机一键恢复命令，恢复前要重新核对目录、权限、CPU 和端口，避免同一身份同时运行。

## 12. 按现象排查

| 现象 | 先核对什么 | 应保留什么 |
| --- | --- | --- |
| 容器未运行 | 状态错误、容器摘要、Docker 是否正常、端口冲突 | 完整数据目录和身份 |
| 运行但未登记 | RPC 是否可用、是否同一创世区块、水龙头登记是否重试 | 原身份，别删密钥重来 |
| 已登记但未计算 | 链同步、任务分配、矿工日志摘要、CPU 与内存限制 | 配置与历史，别盲目多开 |
| 计算结果增加、没有获胜 | 计算结果是否达到链上门槛；提交与获胜是独立字段 | 真实结果，不把它写成已获奖励 |
| QP 不变 | 父钱包、X 资格、官网分类、接口是否识别、观察时长 | 两次带时间的快照 |
| 新账户邀请没显示 | `ref`、受邀方地址、账户实际部署状态、官网同步 | 交易/账户与推荐记录 |

## 13. 常见问题

**显示没有积分，是节点坏了吗？** 不一定。先看查询的 EVM 地址是否正确，再看官网资格和索引状态。节点地址 `5…` 不能直接填进只接受 `0x…` 的 QP 查询框。

**网页显示的钱包怎么和预期不同？** 以页面 `Selected Address` 为准。钱包首页切换账户，有时不会改变这个网站已连接的账户；由本人在钱包的站点连接设置中核对，不要让脚本自动操作主钱包。

**邀请做了，另一边仍是 0？** 核对邀请人 `ref`、受邀方父钱包、账户是否真正创建、X 资格和官方记录。不要把没有同步武断写成失败，也不要把“我操作过”写成已记入邀请。

**运行节点需要先存 ETH 吗？** 本脚本的 Aglais 矿工通过免费 AGLS 水龙头登记。EVM 智能账户创建和真实资产操作可能需要该链 Gas，它们是不同步骤。

**同一 IP 的多个地址有分，是不是我也能固定拿同样的分？** 不能这样推断。公开 IP、硬件描述可能是自报或历史记录；积分是钱包累计值，运行时长和历史配置未必一致。
