## 一、先把参与入口分清

QUIP 的入口不少，我建议先保存下面这几处。

**Quest：https://quest.quip.network/**

社区任务入口。看当前账号能做哪些任务、哪些已经完成，以及相应任务积分。页面里的任务可能有前置条件、每日次数或开放时间。

**Quip Account：https://account.quip.network/**

账户入口。这里要分清当前连接的父钱包，以及创建出来的 Quip 智能账户。进入向导、选择网络和账户部署完成，是不同状态。

**Quip Points：https://points.quip.network/**

查看 QP 和分类明细。登录分、节点分、资产和交换等分类不能混着判断；总分增加，不一定说明矿工有新增产出。

**Mindshare：https://mindshare.quip.network/**

X 内容贡献活动。按活动要求关联 X、提及 @quipnetwork，用原创、有信息量的内容参与，再看官方统计和排名。详细规则与时间核对已放在 GitHub 的活动说明中。

Quest、Mindshare 和 QP 各有统计口径。Aglais 的 AGLS 测试币、链上证明和获胜记录，也要单独看。不要把这些数字直接相加，更不要当成已到账的现金收益。

## 二、开始前，先核对你正在用哪个账号

建议准备一个专门参与项目的钱包，记录公开地址，浏览器和 X 账号也固定下来。每次操作都看网站实际显示的账号，尤其是页面上的 Selected Address。

这里有三个容易认错的地址：

1. EVM 父钱包地址：0x 开头，是连接账户网站、查询公开 QP 时需要核对的地址。
2. Quip 智能账户地址：创建账户后得到的链上账户地址，可能与父钱包不同。
3. Aglais 矿工地址：通常是 5 开头的 SS58 地址，由节点身份生成，不是比特币地址，也不是上面的 EVM 地址。

节点脚本接收的是公开 EVM 地址，用于节点描述中的归属字段。服务器不需要你的 EVM 私钥或助记词。

账户的 X 关联、关注条件和活动资格仍要在官网完成。填了公开地址，并不等于已经授权钱包、完成推荐绑定或满足所有积分条件。

## 三、没有服务器，先做开放任务

先进入 Quest，核对账号和前置任务，再按页面做当前开放的项目。

我的做法是：做一项，核对一项。需要跳转网站的，回来后看任务是否真的完成；需要提交链接的，提交自己实际发布的内容；已经完成的就保留记录，不重复提交。

可以记录五个字段：日期、任务名、使用账号、提交链接、最终状态。积分变化另记一列，这样日后能看出增加来自哪里。

验证码、账号权限、钱包签名或真实资产操作，都要看清楚页面要求。尤其不要因为某个任务还锁着，就直接推断必须充值或交换资产。先确认它实际缺哪一个条件。

## 四、做内容贡献，我会写什么

我更愿意分享别人能照着复现的东西：几个入口怎么区分、一个错误如何定位、运行状态怎么看、某个积分判断为什么不可靠，以及工具如何使用。

这篇文章对应的实际贡献，就是把 CPU 部署和积分核对整理成可复用工具，并把验证范围公开。它能解决具体问题，读者也能检查脚本与说明。

准备发长文章时，我会同时写一条 X 主帖，保留核心结论、@quipnetwork 提及和教程入口。长文章提供完整步骤，主帖让读者先看到文章能解决什么。

邀请链接会明确写是我的推荐入口，不包装成官方唯一入口。内容里也不写“多开几倍收益”“发帖必得积分”这类尚未证明的结论。

发布后保存主帖链接，如果 Quest 页面要求提交，就按当时的页面提交，再核对任务与榜单。发出去了、页面读到了、审核通过和积分到账，仍是不同状态。

## 五、邀请流程最容易错在哪里

邀请链接里的 ref 是邀请人地址。使用我的链接时，ref 是我的 888 地址，而网站连接的钱包应当是你自己的参与钱包。

顺序可以这样走：

1. 在对应的浏览器配置中打开邀请链接。
2. 连接自己的参与钱包，核对 Selected Address。
3. 按官网要求完成账户流程；出现交易时检查网络、账户和费用。
4. 看账户是否真正部署完成，再看推荐记录。

只打开链接，或在创建向导里看到一个待部署地址，不等于账户已经创建。智能账户部署可能需要所在网络的 Gas，而邀请记录也可能需要等待同步。

邀请方可以看推荐人数与已得推荐积分；有明细时再对应到具体账户。没有明细就保留待确认，不把猜测写成结果。

## 六、普通 CPU 节点，先理解它在跑什么

本工具部署的是 CPU 计算矿工。默认每个实例限额 1 核，内存上限 1GiB，通过已有 RPC 连接 Aglais，不为每个矿工重复同步一整套链数据。

计算矿工和正式共识验证者是不同目标。运行这个工具，不等于已经成为获批的验证者。

CPU 也不是“几乎不吃”。矿工忙于计算时，一个实例可以占满一个逻辑核。内存上限则不是预先占满的内存：之前一次五矿工快照里，每个约 16～21MiB，但这只是当时观测，不代表峰值或最低配置保证。

如果服务器还跑完整链节点、面板或其他业务，它们的内存、磁盘和 CPU 要另外算。先用已有机器的小部分资源验证运行，比急着扩服务器更容易判断效果。

## 七、准备部署环境

当前脚本的部署目标是 Linux x86_64，需要 Python 3.10+、Docker Engine 和 Compose 插件。ARM 尚未验证。

可以先检查：

```bash
uname -m
python3 --version
docker --version
docker compose version
free -h
df -h /
```

如果服务器已经有其他业务，先检查余量和现有 Docker。不要因为命令报错，就直接重装整个环境。

## 八、一键启动一个 CPU 矿工

先下载固定版本脚本：

```bash
curl -fL https://raw.githubusercontent.com/q3579338/quip-node-kit/v0.1.0/install.sh -o quip-install.sh
```

把下面两个占位值换成自己的公开 EVM 地址和服务器 IP 或已有入口域名：

```bash
sudo bash quip-install.sh \
  --wallet 0x替换成你的公开EVM地址 \
  --public-host 替换成你的服务器IP或已有入口域名
```

已有服务器可以先加上 --dry-run 查看计划。单独下载的引导脚本会先下载并校验管理程序；Python 管理程序的预演不会启动矿工、创建运行配置或联网核对 RPC。

新装 Ubuntu/Debian 没有 Docker 时，可以显式增加 --install-docker。脚本会使用 Docker 官方软件源；发现已知冲突环境会停止，不自动卸载旧软件。其他发行版先按 Docker 官方文档准备。

首次启动，官方矿工镜像会在本机生成独立测试网节点身份，通过免费 AGLS 水龙头登记。这一步与 EVM 智能账户充值 ETH 是不同流程。

管理端口默认只绑定本机。public-host 是公开节点描述字段，填写 IP 不会自动配置公网访问、防火墙或安全网关；需要对外服务时另行配置。

固定镜像摘要和下载校验用来保持版本一致，不代表所有第三方组件没有风险。脚本、依赖来源和当前兼容范围都已公开，可以先查看再执行。

## 九、启动后看哪些结果

默认 root 部署的检查命令是：

```bash
sudo python3 /opt/quip-node-kit-data/quipctl.py status
```

依次看容器是否运行、节点是否 registered、是否 mining，以及 resultsReceived 是否增加。

resultsReceived 是返回的计算结果数。是否提交证明、证明是否获胜、是否获得链上奖励，还要看对应记录。QP 则回到积分页面看 node 分类。

这次后续新增的一个矿工，核对时已经登记、正在计算，并返回了两个计算结果；当时提交证明仍为零。这个结果可以说明它开始工作了，不能拿来宣称已经获得奖励。

本仓库通过了 16 项离线测试、1/4/5 实例的真实 Docker 配置解析，以及公开引导脚本的下载校验与预演。全新主机安装到最终获胜的完整流程尚未验证，范围写在 validation 文档中。

## 十、一台机器跑多个，要看真实资源

首次部署有足够资源时，可以增加参数：

```bash
sudo bash quip-install.sh \
  --wallet 0x替换成你的公开EVM地址 \
  --public-host 替换成你的服务器IP或已有入口域名 \
  --instances 4
```

每个实例分别保存节点身份，不复制旧密钥。程序优先分配不同物理核心，超过可见物理核心数时，需要明确使用 --allow-smt。

我们后来在 4 物理核、8 线程机器上共跑了 6 个各限 1 核的矿工。后两个用了超线程，与已有实例共享物理核心；这台机器没有因此变成 6 个物理核。资源竞争和有效计算效率要继续观察。

多开是否增加同一钱包的 QP、增加多少，不能只看进程数。不同 IP、IPv6 或代理端口也不是本脚本默认要求，代理端口变化不自动等于出口 IP 变化，更不代表奖励资格变化。

已经部署一个实例后，本版本不会直接覆盖成四个，避免误改身份。新建另一组还需要检查目录、端口和 CPU 是否与旧组重叠，具体见运维说明。

## 十一、积分怎么测，才不会看错

下载完整仓库后，使用自己的公开 EVM 父钱包查询：

```bash
python3 quipctl.py points 0x你的公开EVM地址 --out ./snapshots
```

隔至少 24 小时再存一份，然后比较实际文件：

```bash
python3 quipctl.py compare ./snapshots/第一份.json ./snapshots/第二份.json
```

程序会校验是否同一钱包、账户是否被接口识别、时间顺序是否正确。未满 24 小时只给差值；出现负向修正时，也不硬算日收益。

即使满一天，折算值也只是那个窗口的观察。如果同一钱包还对应其他服务器，得到的是钱包整体变化，不能直接分摊成某一台机器的产出。

公开接口返回 found:false 时，应记作尚未识别，不能把附带的零写成已核实的有效账户余额。累计积分除以节点登记天数，也不能证明稳定日收益。

## 十二、遇到问题，先保留身份

状态没有就绪，先看运行摘要：

```bash
sudo python3 /opt/quip-node-kit-data/quipctl.py logs --instance 1
```

需要停止或重新启动时：

```bash
sudo python3 /opt/quip-node-kit-data/quipctl.py stop
sudo python3 /opt/quip-node-kit-data/quipctl.py restart
```

不要用删密钥、删数据目录的方式处理普通故障。节点身份和历史应停机后备份到自己控制的私有位置，不能上传公开仓库。

容器运行但没有登记，先核对 RPC、水龙头与链版本；正在计算但没有获胜，查看证明与难度相关记录；QP 没变，则核对父钱包、X 条件、接口识别和观察窗口。每一种现象都有不同原因，不需要一看到零就重装。
